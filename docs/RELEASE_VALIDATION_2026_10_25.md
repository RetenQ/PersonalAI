## 真实供应商测试

服务为 DeepSeek，模型 `deepseek-flash`，Chat Completions 使用 `json_object`。仅使用自建案例，不发送用户个人资料。脚本 [tests/live_provider_smoke.py](../tests/live_provider_smoke.py) 不会被 pytest 自动收集，也不会在 CI 隐式调用模型。

案例：阅读十章并逐章留下笔记；已确认当前值为两章；一个关联任务，任务自身进度未知；日志记载读完两章与术语阻碍；中午回顾补充下一步。测试资料只在系统临时目录创建并自动清理。

排查期间进行了多轮手动复验，没有应用内自动重试。最初的完整案例中，模型将目标/任务/追踪配置列入 facts，虽引用真实编号，却缺少活动来源，因此被严格校验拒绝、报告标记 failed。简化的目标加日志案例可通过，帮助定位到混合来源时的语义约束问题。

修正是在日报系统提示中列出已选资料的活动来源与目标编号，明确 facts 不得列目标设定或计划配置。没有改宽 Schema、替换引用、丢弃错误后冒充成功或修改正式资料。增加回归验证：引用目标、任务、追踪配置的事实均拒绝；引用有效日志的事实通过。

最终一轮的两次真实调用均为 HTTP 200，完整流程通过：

| 验证项 | 最终结果 |
|---|---|
| 目标估计 | 15–25%，medium；有一项任务贡献分析，字段和来源校验通过 |
| 已确认进度 | 保留原两章的计算进度，不被 AI 区间替换 |
| 日报 | facts 2、reflection 3、issues 3、suggestions 3、next_steps 3、long_term 1、missing 5；结构与引用通过 |
| 重复提交 | 重复目标分析和日报请求未追加模型调用 |
| 正式计划 | 目标和任务对象未被 AI 修改 |
| 重启/恢复 | 重新打开存储可读取分析与成功报告；备份恢复后的事件逐字节一致 |
| 凭据 | 通过内存管道读取；临时文件与解压后的备份内容均未含明文密钥 |

这里的百分比是测试案例的模型估计，不是用户真实进度或准确率指标。本轮验证真实报告生成与本地管道，**没有验收真实用户资料的建议质量，也没有以真实时钟持续运行定时器**。调度时刻、重启与跨年等逻辑由隔离模拟时钟测试覆盖。少量成功样例不保证后续模型输出总能通过校验；失败应保留明确提示，不自动增加费用。
