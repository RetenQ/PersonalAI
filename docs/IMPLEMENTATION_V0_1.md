# 电脑版 v0.1：实现与验证记录

日期：2026-10-23。依据已批准的首个开发里程碑；本文件补充实现状态，不替代或修改既有需求基线。

## 已实现

React／TypeScript／Vite 构建本地界面；FastAPI 提供 API 和构建后的静态文件。仅挂载首页和构建资源，项目、个人档案和运行数据目录没有静态访问入口。Windows 启动脚本支持显式端口参数，程序只绑定 IPv4 回环地址。

后端为小型单体应用：

- `models` 定义输入、记录、修订提案、确认和事务类型，拒绝额外字段及无效内容。
- `store` 统一写入、跨进程文件锁、校验和、事务事件链与索引重建。每个请求写一个 Markdown 事务，批准修改时记录和提案状态共同提交。相同请求编号和内容返回原结果，编号复用但内容改变返回冲突。
- `backup` 导出带清单的 ZIP、检查路径和容量、验证校验和，并恢复到全新目录；已有目标目录一律拒绝。
- `model_gateway` 只定义输入理解和报告生成的返回类型；生产实例固定为未配置状态，没有服务地址、密钥加载或云端请求。

每个事件文件包含 JSON 格式的 Markdown front matter 及可阅读正文。文件以事务序号和请求 UUID 命名，记录 UUID 和版本在元数据中关联。历史事件保留完整旧记录；当前视图在启动和访问时从文件重建。首版优先正确性，数据量增大后的索引优化留待实测。

## 本机接口

| 接口 | 行为 |
|---|---|
| `GET /api/session` | 建立 HttpOnly、SameSite=Strict 会话 cookie，返回写入校验令牌 |
| `GET /api/status` | 版本、上海日期、模型状态、存储健康及分类 |
| `POST /api/records` | 用户明确新增原文、正式任务或想法；需要请求 UUID |
| `GET /api/records` | 日期、类别、记录类型、关键词查询 |
| `GET /api/records/{id}` | 当前记录与全部修订 |
| `POST /api/records/{id}/revisions` | 基于预期版本提出修改，原记录暂不改变 |
| `GET /api/proposals` | 待处理及已处理确认事项 |
| `POST /api/proposals/{id}/decision` | 接受／拒绝；接受时再次检查当前版本 |
| `GET /api/reports/daily` | 用户记录按日归组，任务单列，缺失保持未知 |
| `POST /api/backups/export` | 导出前在临时目录恢复校验，返回 ZIP |
| `POST /api/backups/verify` | 校验上传 ZIP，不改变当前数据 |

Host 必须为指定端口的 `127.0.0.1` 或 `localhost`。跨站来源被拒绝，写请求同时校验会话 cookie 和令牌；前端资源不加载外部字体、图像或脚本。程序不设置宽松 CORS。无多用户账户系统，本机使用者仍应依靠操作系统账户保护本地文件。

状态码：422 为输入／备份格式错误，409 为重复编号内容冲突、过期修订或已处理提案，403 为来源／会话不符，503 为存储不可用。错误不会被包装成保存成功。

## 未实现与限制

- 云端供应商接入及真实模型能力尚未验收：不自动提取、拆分或分类输入，不自动识别正文中的任务与时间。模型测试替身只在测试中使用。
- 未实现完整六要素日报、周／月复盘、建议执行跟踪、冲突分析、主动通知、定时任务、Dashboard、设备输入或跨端同步。
- 周期备份与保留期限待决定；手动导出包含本应用事件数据，不包含原有档案。备份为明文，校验不是加密。
- 每次查询重新校验事件日志，适合初期个人使用；未做大规模日志性能测试。校验链可发现损坏与中间缺失，但没有外部锚点时不能识别整段末尾历史被完整删除，仍须独立备份。
- 尚未保存的表单内容只在页面内存中；刷新前应自行保留。未开发自动覆盖恢复或批量删除入口。
- 没有部署、发布、创建远端仓库、设置自动启动或改动外部日历／账户。
