# 定时综合分析与建议

实现日期：2026-10-25。优先于此前的快速录入、关注卡与首页视觉优化；这三项尚未开始实现。

## 使用流程

1. 启动本机服务，在设置中保存并启用模型、保存对应密钥。先使用内置示例测试连接，真实服务兼容性仍需实际验证。
2. 在“定时分析与建议”添加每日生成时刻，使用上海时区和 24 小时制。不预填时间，支持最多 24 个不重复时刻。
3. 勾选允许自动发送的资料类型，选择是否请求启用。点击预览，查看修改前后、供应商／模型和当前完整输入样本。
4. 确认范围并保存。启用授权包含所选类型以后新增的记录，不再逐次询问。没有模型或密钥时不能启用，但可保存关闭状态的时间与范围。
5. 在“每日回顾 → AI 定时分析”查看运行情况、六部分分析、缺失信息及来源版本，可下载 Markdown／JSON。这里与原有本地事实汇总分开。

保存原文不会即时调用模型，但已授权范围内的原文会进入之后的定时分析。分析内容为模型输出；引用校验保证编号与版本可追溯，不保证语义判断一定正确。建议不执行、不创建任务、不改变正式进度或画像。

## 数据范围与权限

默认关闭、时刻为空、资料类型未选。可选类型为日常原文、目标及完成标准、任务及追踪、活动日志、早中晚回应、当前状态。

- 日常原文、日志、回应及状态取实际执行当天及之前六个自然日，含首尾；按记录填写的日期筛选，不推测实际发生时刻。
- 目标为取样时全部当前目标；任务为日期不晚于当天的未完成任务，以及窗口内日期的已完成任务，并附对应追踪信息。它们作为计划背景，不能直接视作已发生事实。
- 不读取私人访谈、个性档案、展示简介、想法库、待确认提案、历史 AI 结论或密钥作为模型输入。不自动扩大授权范围。
- 超过 300 项来源或 128 KiB 输入时不调用、不截断，记录明确原因，需缩小资料类型。
- 六部分分别是记录中的事实、进展分析、问题与阻碍、改善建议、下一步参考、与长期目标的关系。每项须引用本次输入编号；无事实来源不能把任务当事实，无目标来源不能生成长期目标关系。缺失信息单列，空栏目显示证据不足。

模型服务地址、名称、输出模式或启用状态与授权时配置不一致时，自动调用暂停；使用新配置需要重新预览确认。仅修改展示名称等无关设置不会撤销授权。密钥仍用 Windows 当前账户保护。

## 时间、补跑和故障

定时器随本地服务启动，每 15 秒检查一次。时刻表示开始生成，不保证那一秒结果已经就绪；没有系统定时任务、开机启动、外部推送或后台服务安装。浏览器关闭不影响仍在运行的本地服务，服务停止则不会运行。

首次启用从确认时间之后开始，不补之前的历史。服务停机、电脑休眠或长时间忙碌后，只执行最近一次已到期时刻，其余旧时刻合并略过。补跑以实际执行日为“当天”，同时记录原计划时刻、实际开始及取样时间，不伪装成过去生成的报告。时钟回拨不会重新补旧时刻。

同一数据目录使用调度锁和运行锁；同时只进行一个定时调用。同一应用内与手动目标分析共享模型锁。锁被其他实例占用时不争抢；若持有调度锁的实例退出，可重启要继续调度的实例。

调用前先保存 running 状态，再调用模型。结果状态包括 succeeded、failed、skipped、interrupted。超时、额度受限、拒绝、格式和引用错误不自动重试；下一设定时刻是一次新的分析。进程中断后，可能已经产生供应商费用，因此标为 interrupted，不重发同一次请求。用户可明确点击“按已授权范围立即生成”新建一次调用；客户端重发同一请求编号则返回原运行结果。

暂停立即阻止后续调用；已经发送的请求无法撤回，仍可能保存返回结果。没有资料时保存 skipped 状态，不制造模拟结果或无数据评价。运行失败不影响原始记录。

## 存储、恢复与外部提醒

新增独立的 `schedule` 和 `scheduled_run` 实体，复用既有事件链；旧版数据不批量改写。已确认设置整理到 `data/user/states/`，运行状态及报告整理到 `data/user/analyses/`，含来源链接并进入完整备份。

本机启用授权单独保存在 `data/.scheduler/consent.json`，不进入备份或导出。恢复后的设置与报告可读，但自动调用保持未授权，必须在新目录重新确认。直接复制整个数据目录会保留授权文件；跨电脑仍需重新填写受 Windows 账户保护的密钥。

对接提醒程序首选本机结果接口：

| 方法与路径 | 内容 |
|---|---|
| GET `/api/schedule` | 保存的配置、版本、授权、模型就绪、下一时刻与调度状态 |
| POST `/api/schedule/preview` | `{data:{enabled,times,scopes},expected_version}`；本地预览，返回十分钟有效的 approval_token |
| POST `/api/schedule/confirm` | `{request_id,approval_token,approved:true}`；确认范围并保存，模型或配置变化则拒绝旧预览 |
| POST `/api/schedule/pause` | `{request_id}`；暂停后续调用 |
| POST `/api/schedule/run` | `{request_id}`；按已授权范围立即运行；等待结果，无后台重试 |
| GET `/api/scheduled-reports?limit=50&offset=0` | 分页报告与依据变更标记；返回 total、next_offset，limit 最大 200 |
| GET `/api/scheduled-reports/feed?limit=50&offset=0` | schema_version=1 的精简运行结果、建议摘要及详情地址，不主动发送 |
| GET `/api/scheduled-reports/{id}` | 报告与来源版本 |
| GET `/api/scheduled-reports/{id}/export?format=markdown` | 下载 Markdown；format=json 下载带格式版本的 JSON |

写操作沿用本机会话与来源校验。外部程序可只读 feed，以 `id + version` 去重，检查 status：仅 succeeded 表示生成成功，running 尚未就绪，其余状态应按原因处理。结果含计划时刻、完成时刻和 stale 标记；长期离线后可分页读取。新报告插入会移动分页位置，消费者仍须自行去重。报告内容是文本数据，不是给提醒程序的执行指令。

没有新增公网接口、Webhook、邮件、系统通知或通知发送时间设置。手机目前不能直接访问本机服务。

## 验收边界

使用独立目录、可控时钟和模拟供应商验证调度及模型返回；浏览器中验证关闭状态的预览、取消、保存、重启回查和报告入口，不使用真实凭据。真实供应商连接、实际报告质量与外部提醒发送不属于已通过的验收。
