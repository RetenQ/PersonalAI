## 本轮决定

用户要求增加少量颜色、减少文案与冗余 UI，并重排总览。针对当前状态的范围，用户明确回复“完全移除”，因此这一项包含服务端和 APK；其余改版限于网页展示。

总览顺序：

1. 标题旁仅显示年份、年度进度条、比例数值。
2. 待确认事项，含设置/插件确认入口及历史展开。
3. 今日任务、快捷记录；有日志或回顾阻碍时显示阻碍。
4. 日期筛选、导出。
5. 目标与任务、其他已完成事项，以及已启用的扩展展示模块。

删除总览口号、解释段落、重复目标摘要、四项统计、个人展示卡和页脚口号。资料仍可在设置维护，没有清空用户资料。已确认进度、AI 估计、未知值、版本冲突和发送授权等必要状态保留。

新增“日志与回顾”导航：活动日志、早中晚回顾在同页，保留日期查询、来源、修订和导出。该页面复用原 Dashboard 数据与编辑/确认流程，是总览插件的另一展示视图；没有复制业务算法或新增读写接口。

年度时间、待确认的位置固定；日志/回顾迁出总览。目标、其他事项与扩展模块仍能调整顺序/隐藏。旧布局事件不重写；设置只显示仍可调整的模块，相邻移动跳过已迁出的模块。其他事项使用与目标相同的卡片结构，以“已完成”文字和绿色标记呈现，不虚构目标进度。

## 视觉

沿用第一轮 design-taste-frontend 方向与中文系统字体。按用户新要求调整色彩比例：白灰底，蓝色用于目标进度和主要操作，绿色用于任务进度/完成标记，琥珀色用于待确认/阻碍。颜色均配文字，不单靠颜色传达状态。

agent-browser 检查桌面、平板和手机。依据 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 检查标题、焦点、对比、触控和溢出；保留既有 SPA 导航与表单提交逻辑，不宣称全项目全面符合规范。

## 当前状态退役与历史边界

- 删除网页状态模块、表单、布局选项、授权范围和阻碍引用；阻碍改为仅使用日志/回顾。
- 移除 `/api/current-state` 路由、客户端 `states` 资源及 `read:states` 范围；设备/Agent 不能再写 `kind=state`，旧凭据也不能重新读该资源。
- Dashboard、快照、增量同步和待确认不再输出状态数据。核心业务校验拒绝新的状态写入和接受旧状态修改。
- 定时分析不再采集状态数据，新的分析预览不接受 `states`。旧安排若包含该范围，投影为暂停，现有授权失效；用户重新选择范围、预览并确认后才可恢复，不自动更改授权。
- APK 移除现状录入、列表、编辑和分析勾选；其他 APK 界面不随网页换样式。
- 保留冻结的 v2 事件模型、旧状态事件、可读归档和备份校验逻辑。它们只是兼容恢复所需的历史内容，不是可继续使用的功能。没有删除历史、批量重写事件或清除本机草稿。旧状态草稿由服务器拒绝提交。
- OpenAPI 生成器与 Agent 文档已更新，不再宣传状态接口。发布时需同时更新后端与网页，手机另行安装新包；旧客户端尝试状态功能会被拒绝。
