# v0.3 配置解耦与实现说明

实现日期：2026-10-25。仍是一个本地服务，不引入数据库或多进程功能服务。

## 使用入口

- 设置现在分为展示资料、个性与协作偏好、首页布局、任务类型、模型连接、密钥、定时分析、插件与接口、数据诊断。
- 分区独立保存与版本检查；展示资料、类型和模型修改先预览确认。首页布局直接保存。一个分区保存失败或成功不会清空其他分区的草稿。
- 在总览顶部选择今天的计划、处理待确认内容或回看已记录的阻碍。快捷记录默认今天：不关联任务保存普通记录，关联任务只保存活动日志。结果与阻碍可以留空，不自动改变任务或目标进度。
- 快捷记录失败保留输入，同一未完成请求重试去重；切换“继续记录进展”的任务保留文字。页面刷新与离开页面仍不会持久保存未提交草稿。

## 实际服务配置

复制 `config/server.example.json` 到被 Git 排除的 `config/server.local.json`，修改后启动：

```powershell
.\Start-PersonalAI.ps1 -Config .\config\server.local.json
# 显式参数覆盖配置文件
.\Start-PersonalAI.ps1 -Config .\config\server.local.json -Port 18765
```

配置字段：host（仅 127.0.0.1）、port、data_dir、plugins。相对数据目录按配置文件所在目录解析；显式 DataDir 按启动工作目录解析。优先级：显式参数 > 指定文件 > 默认值。未指定文件时不自动寻找本地配置。文件错误或未知字段使启动明确失败，不悄悄回退。

端口、目录、插件的变更需手动重启。设置中的服务信息是当前实际运行值。换数据目录是选择另一个资料集，不会自动搬迁现有记录。自定义目录须自行排除版本控制。

## 独立配置与模型连接

`GET /api/config/sections` 返回 user、ui、types、models，每区包含 data、version、origin。`POST /api/config/sections/{section}` 沿用 request_id、data、expected_version、reason。

- ui 立即返回 entity；其他区返回 change，通过 `/api/config/changes/{id}/decision` 接受或拒绝。
- `/api/config/changes` 可回查尚未处理的配置与插件提案；重新打开设置仍可处理。
- `/api/config/connections/status` 只返回密钥存在状态和就绪信息。
- `/api/config/connections/{id}/key` 单独保存绑定已确认地址的密钥。
- `/api/config/connections/test` 接受 connection_id，只用内置示例测试，不读取个人资料。

models 包含 connections 与 bindings；bindings.goal、bindings.schedule 分别选择目标分析、定时分析使用的连接，可以为空。连接有稳定 id、名称和原有 Chat Completions 配置。连接 id 不可通过网页更改；停用不删除历史。

每个连接独立保护密钥，同一服务地址的两组连接也不共用密钥。原有单连接映射为 legacy，沿用旧密钥。新连接密钥位于 `.secrets/connection-<摘要>.bin`，仍用 Windows DPAPI，换账户不能直接复用。

手动目标分析只检查当前所选连接与资料版本，无关展示资料不会使模型预览失效。定时分析绑定连接编号及实际模型配置，改变绑定、模型或地址后旧授权无效；修改另一连接或展示资料不撤销授权。没有就绪连接不自动换供应商。

旧 `/api/settings` 仍可读取合并视图和提出修改。分区出现之后，其写入转为分区提案，模型字段只映射到目标分析当前绑定的连接；没有绑定时要求使用新设置界面。已经产生的旧整份设置提案不能覆盖后来出现的独立配置，需要重新提出。

## 数据兼容与备份

旧事件 1、2 的读取和规范化保持不变。首次读取旧设置仅投影分区，不写迁移事件；确认保存分区时首次追加 `core/config`，保留旧值与提案。这是按需、幂等迁移，不批量重写历史，也不复制私人画像。

事件 3 支持命名空间实体与保存时的 Markdown 展示；未知插件数据也能完整校验、备份及只读查看。插件不可用时不允许修改其内容。原有备份格式 1、2 继续读取；新的 ZIP 外层仍用格式 2，可能包含事件 3，旧版程序不保证能恢复新版数据。

分区与插件资料整理在 `data/user/states/extension-*.md`，总索引追加入口，个人资料页补充当前展示资料。插件渲染结果在写入时保存，恢复无需执行插件代码，避免缺少插件导致备份内容不一致。

服务配置文件、密钥、外部读取授权与定时分析本机授权不进入备份。恢复后重新填写密钥、启用接口和确认定时权限。恢复必须写入新目录；不要使用旧程序覆盖含事件 3 的目录。

## 性能与限制

总览默认保留原 API 的资料文件校验行为。网页使用 `verify_user_files=false`，不重复对可再生成的全部 Markdown 做完整校验；返回 user_files 为 null（未检查），或当前已知的整理错误，不能把 null 解释为已验证。启动、设置诊断和备份仍进行完整检查，原始事件每次查询仍完整校验。

记录页、历史页和任务页才加载对应记录列表，避免总览、设置、报告页面同时请求不使用的数据。未引入依赖文件修改时间的事件缓存，未降低原始记录校验。

真实模型已完成下方初测及后续的目标/日报完整样例验证，详见 [发布验证记录](RELEASE_VALIDATION_2026_10_25.md)；实际资料分析质量、费用与长期兼容性仍待验收。本阶段无通知发送、第三方插件下载、公网认证、自动更新或插件沙箱。

## 本轮验证结果

- 后端全套 **132 项通过**；前端 **18 项通过**；TypeScript／Vite 生产构建通过。
- 浏览器 **12 个配置、41 项独立用例**分批通过：首批 12 项；设备批次 22 项通过、1 项发现刷新时旧读取请求的 WebKit 问题；修复读取取消后，iPad 横屏 4 项重跑与 Chrome／Edge 6 项均通过。重复运行不重复计数。
- 新增验证包括分区隔离、拒绝与过期确认、多连接密钥及绑定、旧 API 适配、插件启停与依赖顺序、失败隔离、未知插件数据恢复、令牌范围与撤销、分页、字段排除、快捷记录去重与失败保留。
- 本地性能样本为独立目录的 1,000 条测试记录，交替运行五轮：包含全量可读文件检查的总览中位耗时 1,417.42 ms，网页使用的总览路径为 473.91 ms，两者均包含完整事件重放校验。此结果是本机样本，不是性能承诺。首次创建可读资料约 18.8 秒，未进行大数据规模或长期运行测试。
- 正式服务在 127.0.0.1:18765 启动为 v0.3.0；原有 11 个事件逐字节未变，资料校验正常。各配置分区仍从旧值读取，未写入测试配置。示例插件关闭，模型未配置，定时分析关闭，外部读取关闭且无令牌。
- 未授权的外部读取返回 401，私人档案、模型密钥、服务配置文件与 AGENTS.md 的静态访问返回 404。
- 手机与平板是浏览器模拟，真实设备、真实供应商分析和公网访问未验收。Firefox 仍保留此前环境限制，未计为通过。后端仅有原有 Starlette/httpx 弃用提示。

### 2026-10-25 真实供应商初步测试

- 服务为 `https://api.deepseek.com`，模型为 `deepseek-flash`，使用官方支持的 `json_object` 输出模式，调用项目现有 `call_model` 并执行原有 Pydantic 字段与来源校验。[官方 JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)。
- 仅进行一次真实请求，返回 HTTP 200，耗时约 4.08 秒；无自动重试。输入为示例阅读目标，任务与日志为空，不含用户画像或真实记录。
- 输出通过字段与来源校验；`low`、`high` 均为 null，`confidence` 为 insufficient，没有将未记录误判为零进度。
- 凭据通过内存管道传入临时测试进程，未写入代码、配置、事件、导出或备份；正式应用未保存连接或密钥，未启用自动分析。
- 此结果仅证明本次真实连接与一种目标分析场景可用，不代表定时报告、真实个人资料分析质量、持续可用性或其他供应商已验收。
