## 安装与启动

环境：Windows、Python 3.12、Node.js 20.19+ 或 22.12+（含 npm）。在项目目录打开 PowerShell：

```powershell
# 首次安装，或更新依赖／重建界面
.\Setup-PersonalAI.ps1
# 日常使用，只需启动这个服务
.\Start-PersonalAI.ps1
```

可选服务配置：复制 `config/server.example.json` 到 `config/server.local.json`，用 `.\Start-PersonalAI.ps1 -Config .\config\server.local.json` 启动。显式参数优先于配置文件；相对数据目录以配置文件目录为基准，修改后需重启。

打开 <http://127.0.0.1:8765/>。在启动窗口按 Ctrl+C 停止服务。没有开机自启、计划任务或隐藏常驻进程。

如果端口被占用或不可用，程序明确报错；可运行 `.\Start-PersonalAI.ps1 -Port 18765`，打开 <http://127.0.0.1:18765/>。只监听 127.0.0.1。手机远程使用需按部署说明配置 HTTPS；本地 APK 调试可使用模拟器桥接或 USB 转发，详见安卓说明。

## 从哪里开始

1. **设置**：填写展示资料、近期关注，添加任务类型，选择首页模块和顺序。现有私人画像不会自动导入。
2. **总览 → 建立目标**：写清完成标准。数值指标填写起点、目标值、当前值；或建立带权重的里程碑。未知留空，不必凑满数据。
3. **对话记录 → 正式任务**：明确创建要做的事。到总览点击“调整追踪”，关联主要目标、选择多个类型，填写任务自己的进度。
4. **活动日志**：记录做了什么、结果和阻碍。新增关联任务日志时，可同时提出进度修改，保存日志后仍需单独确认。
5. **早中晚回顾**：收到其他应用的提醒后，在网页填写回应。未填写表示未知，不表示任务失败。
6. **导出回顾**：选择日期、时段和目标，预览并下载 Markdown 或 JSON。目标、任务和 AI 分析为当前快照，日期与时段筛选日志和回应；不主动发送到其他应用。
7. **维护个人档案**：在设置中的“个性与协作偏好”填写自述、偏好及边界，预览差异后确认。可直接打开 `data/user/README.md` 阅读按类别整理的全部资料；请在网页修改，不直接编辑生成文件。

已有目标、追踪信息、日志、用户资料及模型配置的更正，先形成提案，预览差异后确认；首页布局独立直接保存。旧版本保留，过期提案无法覆盖新内容。没有最终目标的已完成事情可单独记录。AI 建议的“接受”仅保留接受状态，不自动创建任务。

## 进度如何计算

- 数值目标：`(当前值 - 起点) / (目标值 - 起点) × 100%`，显示限制为 0–100%，支持下降型目标。起点与目标值不能相同。
- 里程碑：按权重计算已确认进度的加权平均；默认等权。必要数据缺失时显示“尚无法计算”。
- 任务自身进度独立维护，任务数量不直接决定目标完成度。旧任务“已完成”且尚无追踪配置时显示 100%，旧任务“部分完成”不会猜成 50%。
- 年度时间按 Asia/Shanghai 与公历计算，剩余天数包含查看当日；这是日历时间，不是目标完成度。

## 配置可选的模型分析

1. 在“模型连接”中添加连接，填写支持 Chat Completions 的 HTTPS 地址、模型及输出格式，选择启用，并分别指定目标分析与定时分析使用的连接。保存后预览并确认。
2. 在“密钥与连接测试”选择已保存的连接，单独填写 API 密钥。密钥绑定已保存的服务地址；Windows 默认由当前账户 DPAPI 保护，服务器使用独立主密钥的 AES-GCM。密钥不回显、不进入备份。改服务地址后需重新保存对应密钥，服务器配置见部署说明。
3. 点击“测试模型连接”。仅发送内置示例数据，可能产生一次调用费用。通过只说明连接与返回格式可用，不代表分析质量已验证。
4. 总览中选择目标，勾选允许发送的任务和日志，先预览，再点击“确认发送并分析”。默认不选任何任务或日志。

优先使用严格结构化输出；服务商不支持时，可手动切换 JSON 模式。两种模式都执行本地字段、区间及来源编号校验。供应商拒绝、超时、额度受限或格式错误会明确提示，不自动重试。服务地址不接受 HTTP、URL 内凭据或重定向；客户端不自动读取系统代理配置。

AI 估计区间与已确认进度并列展示，不取平均；没有活动证据不输出百分比。分析引用选中资料的版本，资料修订后标记“依据已变化”。结果记录来源和建议，不会自行改写正式计划。

> 2026-10-25 已用 DeepSeek `deepseek-flash` 验证示例目标分析与六部分日报的真实调用、结果保存、重复请求去重和备份恢复。测试发现并补强了日报事实来源提示，本地严格校验保持不变；缺少证据的场景仍保留未知。凭据仅在测试进程内存中使用，未保存到正式应用配置。真实个人资料的分析质量、持续定时运行和服务器部署仍未验收。日常使用请在本地设置页面填写密钥，不要写入代码或普通配置。

## 定时分析与建议

在**设置 → 定时分析与建议**填写每日时刻，勾选允许发送的资料类型，预览后确认启用。默认关闭，不预填时间；没有就绪模型时可先保存关闭状态的配置。

分析以当天为重点、近七个自然日为背景，输出事实、进展分析、问题、建议、下一步参考和长期目标关系，附来源与缺失信息。在**每日回顾 → AI 定时分析**查看结果、历史版本和 Markdown／JSON 下载。AI 不自动修改任务、计划或画像。

授权包含选定类型以后新增的记录，后续调用不再逐次询问，可能产生模型费用。可随时暂停。服务运行期间定时检查；服务停止时不运行，重启后只补最近一次，不补整段历史。没有资料则跳过，调用失败不自动重试。

提醒发送由你选择的其他应用负责，可读取 `/api/scheduled-reports/feed` 获取运行状态和建议摘要。完整时间规则、授权范围、恢复行为及接口见 [定时分析使用说明](docs/SCHEDULED_ANALYSIS.md)。

事件文件带完整性校验和、版本与修订关系。请通过应用更正，不直接编辑事件文件。旧版事件继续按原格式校验，新版事件追加写入，不重写旧记录。

`data/user/` 在启动和网页保存后自动整理，各类资料有中文索引，单份文件包含统一栏目、编号、版本、时间与来源链接。设置中的“用户资料文件”显示整理状态并提供重新整理入口。个性只来自你明确填写和确认的内容，不自动导入旧访谈。[完整目录与存储规范](docs/USER_DATA_STORAGE.md)。

在设置或侧栏打开“备份与恢复校验”：

- 导出前在独立临时目录恢复并校验。格式 2 包含应用事件、网页维护的个人档案、非敏感设置及可读资料；当前版本继续支持格式 1 旧备份。不包含密钥、旧访谈原件、程序、user-edits/ 或自行添加的文件。
- 校验 ZIP 不覆盖当前数据。备份是**明文**，需自行保存在可信位置；完整性校验不是加密。
- 换电脑恢复后需要重新填写密钥。定时设置与报告进入备份，但本机启用授权不进入备份；恢复后需重新预览确认才能自动分析。自动周期备份和保留规则尚未设置。


## 常见问题

- **页面还是旧版**：停止原服务，运行安装脚本重建界面，再启动并刷新网页。
- **会话失效**：服务重启后刷新网页重新建立会话。未提交表单只保存在页面内存，刷新前先保留输入。
- **模型不可用**：检查已确认的服务地址、模型、启用状态和匹配密钥；查看供应商是否支持所选输出格式。本地保存与计算不依赖模型。
- **记录格式损坏**：应用暂停读取／写入并明确提示；从已验证备份恢复到新目录，不手动修改校验和。
- **可读资料未同步**：原始记录以网页保存结果为准。在设置中检查资料状态，修复目录权限或空间后点击“重新整理资料”。外部编辑过的生成文件会先保留副本，再更新；不会自动导入网页。
- **备份上传过大**：网页验证上传上限 32 MB，解压内容上限 256 MB。更大规模数据需后续优化。
- **无法从手机访问**：检查 HTTPS 地址、代理与登录/设备授权。本机回环地址不能直接用于远程手机，不要把监听地址改成公网地址。
