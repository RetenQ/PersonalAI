# 用户资料的规范化存储

日期：2026-10-24。依据用户本轮要求实现：用户的信息应规范、人类易读地存放在项目子目录。用户已选择“主要在网页维护，文件自动整理供阅读和备份”。

## 阅读入口与目录

默认入口为项目根目录下的 `data/user/README.md`。使用 `--data-dir` 时，目录随数据位置一起变化，始终在 `<数据目录>/user/`，测试不会写入正式资料。

```text
data/
├─ user/                       自动整理的人类可读资料
│  ├─ README.md                总索引、版本、分类与维护规则
│  ├─ profile/
│  │  ├─ README.md
│  │  └─ PROFILE.md            展示名称、简介、个性自述、偏好与边界
│  ├─ goals/                   一个目标一份 Markdown
│  ├─ tasks/                   一个正式任务一份 Markdown
│  ├─ ideas/                   想法，与正式任务分开
│  ├─ records/                 日常记录原文
│  ├─ logs/                    活动、结果、阻碍和关联来源
│  ├─ checkins/                带日期与早／中／晚时段的回应
│  ├─ states/                  带日期状态及 FOCUS.md 近期关注
│  ├─ analyses/                AI 估计、证据、建议与过期状态
│  ├─ confirmations/           待确认、已接受、已拒绝的提案
│  └─ .manifest.json           自动生成的校验与同步索引
├─ events/                     权威记录、历次修订与确认事件
├─ user-edits/                 检测到外部改动时保留的副本，按需产生
└─ .secrets/                   Windows 账户保护的模型密钥，按需产生
```

每类都有中文索引。业务文件采用完整稳定编号命名，正文标题显示实际名称；修改任务名称、目标标题或日志日期不会导致文件换位置。编号异常时使用摘要作为安全文件名，不把用户输入直接当路径。

## 单份文件的规范

每份业务 Markdown 包含：

- 简短的元数据：格式版本、类型、编号、修订版本、资料层次、来源、创建／更新时间、时区及对应事件版本。
- 中文标题与固定栏目。任务包含原始表述、执行状态、主要目标、类型标签、任务自身进度及关联日志；目标包含完成标准、计算依据与关联任务。
- 相对链接：关联目标、任务、日志与历史来源可以在本地 Markdown 阅读器中跳转。
- 来源与修订：链接到原始事件，能查看旧版与当时的确认过程。

长期档案（L1）、带日期状态（L2）、可追溯记录（L3）、分析及待确认内容（L4）分开；正式目标和任务单独标为计划。未知不写成零，未回应不写成未完成；AI 估计不会写入已确认进度。

## 网页维护与个人档案

“设置 → 个性与协作偏好”支持四个可留空的栏目：个性与自我描述、重视的事情、协作与生活偏好、个人边界。

首次保存和后续修改均先产生提案，显示差异，再确认保存。拒绝或过期提案不会覆盖正式档案，旧版本保留。这里记录的是用户自述，不是人格诊断。原有 `personal/` 与全局访谈档案保持原样；没有自动导入，也没有从日常行为生成个性描述。

新档案独立于应用设置保存，旧版 settings 事件不会因新增字段而被重写。已实现的目标分析仍只发送明确选择的目标、任务和日志，不自动包含个人档案。

## 同步、异常与恢复

网页提交先保存权威事件，再自动整理可读文件；启动时也会重建。所有生成操作共用写锁，每份文件采用临时写入和原子替换，最后更新校验索引。

生成目录不是多文件瞬时替换；生成期间可能短暂存在不同版本的文件。索引在全部完成后才更新，状态检查会比较来源版本及文件校验值，避免把不完整整理报告为成功。没有大规模数据性能验收。

若原始事件已保存、后续生成失败，保存不会被误报为丢失；网页提示可读资料未同步。可在“设置 → 用户资料文件”查看位置与状态并点击“重新整理资料”。修复目录权限或空间后重建不会新增业务记录或重复提交。

不要直接编辑生成文件。同步时若发现其内容与上次生成值不符，会先将原字节保存到 `data/user-edits/<批次编号>/` 再更新，并在设置中显示保留数量；手动内容不自动导入网页。缺失文件与损坏的生成索引可以重建；原始事件损坏时停止整理，保留上次可读资料供查看。拒绝通过符号链接或目录联接写到其他位置。

## 备份与隐私

应用 ZIP 备份格式升级为 2，包含 `events/` 与由同一事件快照生成的 `user/`。恢复时校验文件摘要、历史链，并比对可读资料与事件重建结果。格式 1 的旧备份仍可由当前版本恢复，并自动生成可读目录；旧版本程序不保证能读取格式 2 备份。

仅复制 `data/user/` 可以离线阅读，但不足以完整恢复应用。完整恢复请使用应用 ZIP，或保留整个数据目录。密钥、旧访谈原件、外部改动副本 `user-edits/` 及用户自行放入的额外文件不属于应用 ZIP 范围；需要时单独保管。

整个 `data/` 已排除版本控制，静态文件服务不开放 `data/user/`。文件与备份为本机明文；整理与备份不触发云端分析。

## 验证

本轮结果：87 项后端测试、10 项前端组件测试、4 项浏览器完整流程通过，生产构建通过。浏览器视口为 1440、834、390、320 像素宽度。正式数据初始化生成 24 份 Markdown；原有 11 个事件逐字节未变，没有新增人格描述或接受原有待确认计划。变更前保留了独立备份，新的完整备份也通过临时目录恢复校验。

后端验证覆盖初始空档案、确认／拒绝／过期、稳定路径与来源链接、未知进度、生成失败与去重、写入中断、外部改动保留、文件及索引恢复、历史损坏保护、旧备份兼容、新备份逐文件恢复与不一致拒绝、目录边界、访问校验及档案不自动进入分析。

浏览器流程在电脑、平板、两种手机宽度下验证档案差异确认、读取实际生成文件、重新整理及备份恢复。测试写入独立 `.cache/browser-e2e/`；没有给正式用户填入测试个性或偏好。
